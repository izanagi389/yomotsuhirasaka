# AI向け配信

主な相手は、記事を読んで引用するAI（AI検索やアシスタント）。学習用クローラーへの最適化は対象外（Q33）。エージェントによる直接の呼び出しは、当初は対象外としたが、MCP として提供する（2026-11-25、下記「MCP」）。

## 提供方法（Q34）

- AIが読みに来るのは利用者の公開サイトのドメイン。CMSは素材を作って渡すまでを担う。
- コアは、形式に依存しない素材を配信APIで返す。
  - 記事ごとのMarkdown版: 固定アンカーID付きの見出し、出典として使えるURL、最終更新日、訂正履歴、削除済みアンカー、シリーズや前提知識の関係（関係の種類と相手の記事のURL）
  - 記事一覧の目録データ
- 連携部品（最初はNuxtモジュール）が、`/llms.txt` や記事のMarkdown版を生成してサイトに置く。ビルド時の生成と、サーバーのルートとして返す方式（SSRのサイト向け。キャッシュ付きで、CMSからの記事の状態変化のWebhookで消す（Q146））の両方に対応する（Q145）。`llms.txt` は提案段階の形式なので、素材と出力を分けておく。

## 対象の制御（Q35）

- チャットボットの対象とは別のスイッチで制御する。
- **フィールド単位**: Markdown版にどのフィールドをどう並べるかを、開発者がスキーマで決める。指定していないフィールドは含めない。
- **記事単位**: 「外部AI向けの素材に含める」を編集者が切り替える。初期値は「含める」。OFFの記事は、Markdown版・目録・他の記事の関係の相手のいずれにも含めない（Q63）。
- `devNote` は含めない。
- 版の本文を抹消したら、その版から作った保存済みの素材も削除する（Q134, Q144）。

## 学習への利用の拒否（Q35）

- 記事単位で「学習への利用を拒否」を選べる。連携部品が、対応するメタタグや `robots.txt` の記述を生成する。
- これはクローラーへの意思表示であり、技術的に阻止するものではない。管理画面にその旨を明記する。

## 出し分け用のメタデータ（Q64）

- 読者ごとの出し分けはCMSでは行わない。CMSは材料だけを返す。
  - 読了時間: 変換器の出力から自動で計算する
  - 難易度や対象読者: スキーマのフィールドとして定義する
- 出し分けの方法は、すべてサイト側に任せる。

## MCP（2026-11-25、持ち主の判断）

AIエージェント（AIのアシスタントや開発の道具）から、CMSの記事を検索して読んだり、下書きを書いたりできるように、MCP（Model Context Protocol）のサーバーをCMSのサーバーに組み込む。

- **通信の方式**: Streamable HTTP。CMSのサーバーの1つの口として提供し、別のプロセスは動かさない。
- **読む**:
  - 配信APIのキーで認証する。キーのワークスペースの、公開中の記事だけを返す。
  - 検索・記事の取得は、配信API・サイト内検索と同じアクセス制御の層（`08-search-and-related.md`「共通の層」）を通す。「見せてよいもの」の判定を別に持たない。
  - 返す内容は、AI向けのMarkdown版と同じ規則に従う（「外部AI向けの素材に含める」がOFFの記事、指定していないフィールド、`devNote` は返さない）。
  - 配信APIのキーと同じ回数制限をかける。
- **書く**:
  - 個人のトークンで認証し、その人のロールの範囲で、下書きの作成と変更だけを許す。公開、予約、削除、訂正、スキーマの変更、権限の変更はできない。
  - 配信APIのキーでは書けない。
  - 書いた内容は、管理画面からの保存と同じ検証（本文の検証、楽観ロック）を通す。
  - 誰がMCPで書いたかを、監査ログに残す（内容は残さない。原則7）。
  - MCPで書き込むエージェントは、読んだページや文書に埋め込まれた指示（プロンプトインジェクション）に従ってしまうことがある。手順書に、書き込みのトークンには最小の範囲と短い有効期限を付けること、公開は人が確かめてから行うことを書く。
- 提供する道具（tools）の一覧と、個人トークンの範囲の名前は、実装の前に決める。
