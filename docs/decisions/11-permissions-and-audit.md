# 権限と監査ログ

## ロールと権限（Q76）

固定のロールはM1、重い権限の個別付与とレビュー依頼はM2（Q88）。

- 基本は固定のロールとする。

| ロール | 主な権限 |
|---|---|
| 管理者 | ワークスペースのすべての操作、重い権限の付与 |
| 編集者 | 記事の作成・編集・公開、訂正としての公開、確認済みの記録、レビュー |
| 執筆者 | 記事の作成・編集、レビューの依頼、原文の更新の反映済みの記録（Q164）。公開はできない（Q77） |
| 閲覧者 | 閲覧のみ |

- 重い権限だけは、個人に追加で付与できる。
  - 質問ログの閲覧（**どのロールにも既定では付けず、管理者だけが付与できる**）
  - LLMの接続設定と予算の変更
  - 学習への利用の拒否など、サイトの方針に関わるスイッチ
  - 訂正としての公開、確認済みの記録
  - 編集の引き継ぎ
- 細かい権限を自由に組み合わせてロールを作る仕組みは作らない。
- 上の表で確定する（Q192）。あわせて、次のとおりとする。
  - 執筆者は、他の人が書いた記事も編集できる。
  - 編集者は、記事を削除できる。執筆者は削除できない（削除できるのは管理者と編集者だけ。Q200）。
  - 閲覧者は、下書きも見られる。

## ワークスペースと利用者（Q101, Q117, Q121）

ワークスペースの管理者どうしは互いに信頼しない（`13-security.md` の脅威モデル）。利用者はインスタンス単位で存在し、複数のワークスペースに所属できる。

- ワークスペースの作成は、サーバー管理者だけができる。
- 招待は、相手が既存の利用者でも、本人の承諾があって初めて所属させる。招待の操作への応答は、相手が既存の利用者かどうかで変えない。
- ワークスペースの管理者に見えるのは、自分のワークスペースの所属者だけ。他のワークスペースの利用者の存在を知る手段を作らない。
- 所属者の一覧は、ワークスペースの管理者とサーバー管理者が見られる。管理者は、他の所属者に「所属者の一覧の閲覧」の権限を個別に付与できる。この権限はM1から入れる（Q190）。
- ワークスペースの管理者がパスワードや多要素認証のリセットを発行できるのは、自分が管理者であるワークスペースにしか所属していない利用者だけ（詳細は `13-security.md`）。

## 監査ログ（Q80, Q81）

記録はM1から始める。画面と外部への書き出しはM2（Q88）。

### 記録するもの

- 重い操作を記録する: ログイン、ロールや権限の変更、APIキーの発行と失効、LLMの接続設定と予算の変更、質問ログの閲覧、編集の引き継ぎ、スキーマのデプロイ、訂正としての公開、訂正による予約の自動取り消し（Q133）、版の本文の抹消（Q134）など。
- 記事の内容の変更は版の履歴に任せ、監査ログには「誰が、どの記事の、どの版を作ったか」のIDだけを残す。
- **記事の本文や訪問者の質問文などの内容は一切書かない。** IDと操作の種類だけを残す。
- 例外として、管理者への通知の急増の記録（ログイン失敗・回数制限への到達。インスタンス単位）には、件数・期間と、件数の多い順に最大10件ずつのIPアドレス・利用者のID・メールアドレスを残す。メールアドレスは存在するアカウントのものだけとし、存在しないアドレスへの試行は件数だけにする（入力された任意の文字列を残さない）。インスタンス単位の記録なので、サーバー管理者とインスタンス全体の書き出し先にだけ出る（Q174の補足、M2の計画の15番）。

### 保護と保存期間

- 監査ログは追記のみ。管理者であっても、管理画面や管理APIから編集・削除できない。
- DBの権限でも守る。普段の処理用のDBのロールからは、監査ログのテーブルのUPDATEとDELETEの権限を取り上げる。保存期間を過ぎたものの削除は、専用のロールだけが行う（Q111）。
- 保存期間は設定でき、既定は1年程度。期限を過ぎたものは自動で削除する。

### 閲覧の範囲

- インスタンスとワークスペースに分ける。
  - ワークスペースの管理者は、自分のワークスペースのログだけを見られる。
  - インスタンス全体のログ（エンドポイントの許可リストの変更、ワークスペースの作成、テンプレートのデプロイなど）は、サーバー管理者だけが見られる。
- サーバー管理者がワークスペースのデータを操作したとき（リセットの発行、所属の変更など）は、そのワークスペースの監査ログにも記録し、ワークスペースの管理者が見られるようにする（Q122）。

### 外部への書き出し

- 標準出力・ファイル・Webhookなどに、1行1件のJSON形式で同時に書き出せる。
- 外に書き出したものはCMSの自動削除の対象外とし、保管は運用者の責任とする。
