# LLMの接続設定・予算・編集者向けのAI支援

## 接続方式（Q6, Q7）

- 埋め込みも生成も、外部のOpenAI互換APIに統一する。Ollama、llama.cpp、vLLM、LM Studioなどのローカル実行や、Hugging Faceの推論サービスもこの口で使える。
- CMSのプロセス内ではモデルを動かさない。
- 互換実装ごとの挙動差を避けるため、JSONモードやツール呼び出しなどの高度な機能に依存しない。

## 接続設定の単位（Q26）

- インスタンスの既定値＋ワークスペースごとの上書き。上書きの可否と範囲はサーバー管理者が制御する。
- ワークスペースは、サーバー管理者が許可したエンドポイントの中からしか選べない（SSRF対策）。APIキーとモデル名はワークスペースで設定する。
- APIキーはDB内で暗号化して保存し、保存後は管理画面にも管理APIにも再表示しない。

## 予算（Q13, Q70）

- 予算の上限は、入力・出力別のトークン数で持つ。単価を設定した場合だけ、金額に換算して表示と見積もりを行う（Q138）。
- 使用量（usage）を返さない実装では、文字数から多めに推定して数える。推定は上限を超える側に倒さない（Q138）。
- ワークスペースごとに、次の3つの予算を分けて持ち、それぞれ上限（月ごと・日ごと）を設定できる。

| 予算 | 使い道 | 尽きたとき |
|---|---|---|
| 訪問者向けの回答 | 回答の生成 | 予算切れの専用エラーコードを返す（Q21） |
| 編集者向けの支援 | 矛盾の検知など | 支援の部分に「今月の上限に達しました」と表示する。公開は妨げない |
| 埋め込みの作成 | 公開・更新、モデルの変更、変換器の変更による埋め込み。訪問者の検索語と質問文の埋め込みは、同じ上限で別に数える（2026-11-09、第三者の確認の R18） | 再計算を一時停止し、それまでの埋め込みで動かし続ける。訪問者の分が尽きたら、キーワード検索だけで動かす（記事の分は減らない） |

- 大量の再計算（モデルの変更、変換器の変更）は、実行前に件数とトークン数（単価があれば費用）を見積もって表示する。

## 編集者向けのAI支援（Q69, Q70。2026-11-17 に変更）

CMSの文脈を使う支援に加え、一般的な執筆支援も提供する（2026-11-17、持ち主の判断。当初は「CMSの文脈を使う支援だけを提供し、校正・要約・タイトル案・代替テキストの生成などの一般的な執筆支援は提供しない」としていた）。

- 矛盾の検知を除き、どれも編集者がボタンを押したときだけ動かす。
- どれも「編集者向けの支援」の予算の範囲で行う（INV-BUD-03）。予算が尽きても公開は妨げない（INV-BUD-02）。
- AIの提案は、編集者が「当てる」を押すまで下書きを変えない。支援のAPIは下書きを書き換えない（INV-EDIT-02）。
- 日本語の記事では、日本語でない出力を1回だけ取り直し、それでも違えば出さない。
- 管理画面では、記事の編集画面の右の欄の「AI」タブにまとめる。

1. **矛盾の検知**: 公開の確認画面で自動実行する。埋め込みで意味の近い他の記事のチャンク（上位数件に限る）を探し、内容の食い違いをLLMで確認する。
2. **見直しの手がかり**: 確認期限切れの記事を開いたとき、古くなっていそうな箇所（バージョン番号、価格、日付、外部リンク）を強調する。編集者がボタンを押したときだけ動かす。
3. **書くべき記事の構成案**: 答えられなかった質問のまとまりから、新しい記事の構成案を作る。編集者がボタンを押したときだけ動かす。
4. **構成の確認**（2026-11-17）
   - a. 見出しの形（見出しの段の飛び、空の見出し、同じ見出しの重複など）を、AIを使わずにコードで検査する。書いている間ずっと表示する。
   - b. 論理の流れ: 見出しの並びと各セクションの要点から、順番の入れ替え・抜け・重複を指摘する。
   - c. 答えられなかった質問: この記事に意味の近い、答えられなかった質問のまとまりのうち、記事がまだ答えていないものを挙げる。
   - d. 近い記事との重なり: 意味の近い公開済みの記事（上位数件。矛盾の検知と同じ探し方）と内容が重なる部分を挙げ、リンクで済ませる・違いをはっきりさせるなどを指摘する。
   - b〜dは1つのボタンでまとめて実行し、押す前にトークン数の見積もりを表示する。指摘だけを出し、当てるものはない。
5. **校正**（2026-11-17）
   - 「誤り」（誤字脱字、同じ記事の中の表記ゆれ、明らかな文法の誤り）と「読みやすさ」（文の単位の書き換え）の2種類に分けて出す。
   - 見出しのセクションごとに分けて送る。押す前にトークン数の見積もりを表示する。
   - 当てられるのは、元の語句や文が同じ段落の中に1か所だけあり、リンクや太字などの書式を含まないものだけ。CMSのコードで確かめ、満たさない提案には当てるボタンを出さない（原則4）。
6. **要約とタイトルの案**（2026-11-17）
   - タイトルの案はコンテンツタイプの `titleField`、要約の案は `summaryField` で指定したフィールドにだけ当てられる（`02-schema-and-delivery-api.md`）。指定がなければボタンを出さない。
7. **代替テキストの案**（2026-11-17。`03-content-and-editing.md` の Q75 を変更）
   - ワークスペースのLLMの設定で「画像を読むモデル」（任意）を設定したときだけ使える。接続先は、サーバー管理者が許可したエンドポイントの中から選ぶ。画像の入力はこの機能だけで使い、ほかの機能は画像の入力に依存しない。
   - 送るのは、5MB以下のラスター画像（JPEG・PNG・WebP・GIFの1枚目）と、その前後の段落だけ。SVGと大きすぎる画像にはボタンを出さない。画像はサーバーが自分のメディアの保存先から読み、外部への送信の共通の仕組みで送る。
   - ボタンは、画像の代替テキストの入力欄の横に置く。「AI」タブには代替テキストのない画像の一覧を出し、そこからも1枚ずつ案を出せる。
   - 当てた代替テキストは、編集者が書いたものと同じに扱う（公開の条件を満たす）。

支援を有効にする画面に、「公開前の下書き（代替テキストの案では画像も）が、外部のLLMの提供会社に送られます」と表示する。機密性の高いサイトには、ローカルのLLMを推奨する（Q177）。
