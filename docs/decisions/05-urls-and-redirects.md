# 公開URLとリダイレクト

## 公開URLの定義（Q38）

- 記事の公開URLは、ロケールごとに持つ（Q135）。スキーマにコンテンツタイプとロケールごとのURLテンプレートとして書く（例: `https://example.com/{locale}/blog/{slug}`）。
- セクションへの直リンクは、固定アンカーIDを `#` で付け足す。
- テンプレートで表現できない場合は、フックと同じ仕組みでURL生成関数を書ける（M2から。M1はテンプレートのみ）。
- URLの情報源はスキーマの1か所だけ。チャットボットの出典、AI向け素材、プレビューのすべてがこれを使う。

## 計算と保存（Q39）

- URLは公開時に計算してDBに保存する。回答や素材では保存値を使う。
- テンプレート・URL生成関数・依存先のデータが変わったときは、影響する記事のURLを再計算するジョブを回す。
- 回答キャッシュには、URLそのものではなく「どの記事のどのアンカーか」を保存し、返すときに保存済みのURLを引く。

## 変更履歴とリダイレクト（Q40）

- 公開URLが変わったら、変更前と変更後の対応を変更履歴に記録する。**M1から記録する。**
- M1では、取り込みCLIがリダイレクト設定ファイルを一度だけ書き出す（Q132、`03-content-and-editing.md`）。
- リダイレクトの一覧をAPIで返す（M2）。連携部品がビルド時に、サイトのリダイレクト設定（Nuxtのルールやホスティングのリダイレクト設定ファイル）を自動生成する。SSRのサイトでは、連携部品がサーバー側でリダイレクトの一覧を参照して転送する方式にも対応する（キャッシュ付き、Webhookで更新）（Q145）。
- 削除した記事は「消えた（410）」として一覧に含める。
- A→B→Cのように複数回変わった場合は、一覧を返す時点でA→Cに解消する。
- 既存ブログからの取り込みでは、元のサイトのURLを変更履歴に登録する（Q74）。
