## やり方

設計の議論を見ていないエージェント4つに、決定の文書とコードだけを渡し、攻撃者の視点で確かめさせた（`docs/history/` は読ませていない）。範囲は、認証とアカウント／分離・DB・鍵・デプロイ・組み込みJS・配布／配信・本文・メディア・外部への送信／LLM・回答・予算・ログ・監査の4つ。その後、主な指摘を実際のコードと突き合わせた。

### このやり方の限界

- **同じ会社のAI:** エージェントはこの作業と同じ Claude で、議論の文脈がないだけ。別の会社のAIや人の確認の代わりにはならない。
- **読んだだけ:** サーバーを動かす攻撃はしていない。動かして確かめたのは、URLの絞り込みの写しと SDK の解析だけ。実機の確認は侵入テストに任せる。
- **見ていない範囲:** 各範囲で読みきれていない部分がある。管理画面（Vue）の大部分、`cli/` の取り込み、依存の既知の脆弱性の実行結果などが主なもの。
- **先入観:** 2つのエージェントが、起動時に渡されたメモの索引の題名は目に入ったと報告している。

## 結果の概要

ワークスペースをまたぐ読み取り、SQLインジェクション、サンドボックスの脱出、保存型XSS、SSRF、デプロイの検査の迂回は、見た範囲では見つからなかった。

- 1つのワークスペースや匿名の訪問者が、インスタンス全体を止められる問題
- 決定の文書や約束に書いてあるのに、実装されていない・足りない問題（INV-AUTH-05、INV-AUTH-09、INV-QA-11 に反するものを含む）

## 要確認（コードだけでは決められないもの）

- **1人だけを止める手段:** `disabled` を見るコードはあるが、`true` にする処理がない（grep で確認）。退職者などを止められない可能性がある。
- **SSOだけの利用者のリセット:** IdPから外された人が、メールを読めればパスワードのログインを得られる。
- **SMTPなしのリセットのリンク:** ワークスペースの管理者が、同僚の管理者を実質的に乗っ取れる。Q117の範囲として受け入れているかの確認。
- **SSOのログインの古いセッション:** パスワードのログインと違い、古いセッションを失効させない。
- **緊急停止の範囲:** プレビュー用トークン、リセットと招待のトークンは失効しない。
- **プレビューのHTMLのキャッシュ:** SSRのHTMLに `no-store` が付かないようで、URLだけでキャッシュするCDNで下書きが出ないかの確認。
- **リンクの `target`、ライブプレビューの iframe の `sandbox`:** `window.opener` や管理画面の移動に使えないかの確認。
- **検索語の記録:** 検索語が GET の `variables` に載り、プロキシやCDNのログに残る（原則7）。
- **DBへの接続の TLS:** 手動導入で別ホストのDBを使う場合の方針。
- **実機で確かめるもの（侵入テストへ）:** R1 の止まり方、パスワードの照合の同時実行、ヘッダーの読み取りの時間の上限、デプロイのアドバイザリーロックの残り方、QuickJS の割り込みの効き方、日本語でのトークン数の見積もり。
- **GitHub の設定:** ブランチ保護、Code Owner の必須化、タグの保護、Environment `release`、非公開の脆弱性報告。

### 受け入れたもの

- **R14 の残り:** 版の数の上限は付けない。公開の回数は管理APIの回数で抑えられる。→ 2026-11-10、持ち主の判断で受け入れをやめて直した。記事ごと（既定1,000版）とワークスペースごと（既定50万版）の上限を付け、超えたら公開を `too_many_versions` で断る。古い版は消さない（原則8）。
- **R17 の残り:** 匿名の訪問者のメディアへのリクエストに回数の制限はない。帯域はリバースプロキシや CDN で守る。
- **R26:** 取り込みの `originalUrl` で、同じオリジンの CMS の外のページを 301 にできる。信頼された役割の、旧 URL を引き継ぐ機能そのものなので、手順書に注意を書く。→ 2026-11-10、持ち主の判断で受け入れをやめて直した。Nuxt モジュールは、サイト自身の固定のページとモジュールのルートには CMS のリダイレクトを当てない（ビルド時の `routeRules` からも除く）。取り込みで旧 URL を同じオリジンに限る案は、別のドメインからの移行の記録（`INV-IMP-02`、別のオリジンの規則はそのサイトが扱う設計）と食い違うので採らなかった。
- **R27:** リセットの発行の成否で、他のワークスペースへの所属が分かる。発行できる権限そのものから分かる情報で、文言では隠せない。
- **R42:** 登録済みクエリでデプロイを止められる。`INV-SCH-03` が求める動きで、サーバー管理者が `--allow-broken-queries` で通せる。手順書に書く。

### R34 の残り

ワークスペースのトランザクションを持たず、1文で変更する操作（キーやトークンの失効など）は、変更と記録が別のままである。間に失敗すると記録が欠けるが、窓は短い。

2026-11-10: 持ち主の判断で、受け入れをやめて直した。キー・招待・個人トークンの失効、Webhook の削除、予算と上限の変更、LLM の接続設定の削除、埋め込みの切り替えの開始、関連記事の再計算、質問ログの候補の削除、公開・非公開・削除・設定の変更・予約の取り消し、翻訳の作成、メディアのアップロード、TOTP とパスキーの登録、ログイン、サーバー管理者の作成（CLI）を、変更と同じトランザクションで記録する。テンプレートのデプロイとワークスペースの移行の記録は、R42 の修正で合わせて直す。次のものは対象にしない。ワークスペースの作成（スキーマとロールの作成が別の接続のため）、CLI の鍵のファイルの操作（DB の変更ではない）、予算切れなどの出来事の記録（組になる変更がない）。
