# 用語集

| 用語 | 意味 |
|---|---|
| インスタンス | 動いている1つの CMS のサーバーと DB。1つのプロセスで動かします |
| ワークスペース | インスタンスの中の、独立した1つのサイトのデータの単位。データ、検索用のデータ、予算、監査ログを分けて持ちます |
| サーバー管理者 | インスタンス全体を管理する人。ワークスペースの作成とテンプレートのデプロイができます |
| テンプレート | ワークスペースの構造（コンテンツタイプ、フィールド、ロケール、関数）を書いたファイルのまとまり。リポジトリの `templates/<名前>/` に置きます |
| マニフェスト | CLI がテンプレートから作る1つの JSON。サーバーはこれを受け取ります |
| デプロイ | テンプレートをサーバーに適用すること。同じテンプレートを使うすべてのワークスペースに反映されます |
| 移行待ち | スキーマの移行に失敗して再試行を待っている状態。配信は続きますが、そのワークスペースの編集と公開は止まります |
| コンテンツタイプ | 記事の種類（例: `post`） |
| 翻訳グループ | 同じ記事の、ロケールごとの記事のまとまり |
| 下書き | 編集中の内容。自動で保存され、公開するまで外に出ません |
| 版 | 公開するたびに作られる、その時点の記事の記録 |
| 固定アンカーID | 見出しに振られる、変わらない ID。セクションへのリンクと出典に使います |
| 訂正として公開 | 誤りの訂正であることを記録して公開すること。訂正の説明と影響したセクションが公開されます。変更前の本文や差分は公開されません |
| 版の本文の抹消 | 版の番号や日時の記録を残して、本文だけをすべての API から消すこと |
| 鮮度 | 最終確認日と確認期限。内容が今も正しいかを記録するものです |
| 配信API | サイトのサーバーが記事を読むための GraphQL の API |
| 登録済みのクエリ（Persisted Query） | あらかじめサーバーに登録したクエリ。本番の配信 API は、登録済みのクエリだけを実行します |
| 配信APIのキー | 配信 API を使うためのキー（`yomi_key_` で始まる）。ワークスペースごとに発行します |
| 個人トークン | CLI で使う、人ごとのトークン（`yomi_pat_` で始まる）。管理画面の「アカウント」→「個人トークン」で発行します |
| プレビュー用トークン | 1つの記事の下書きだけを短い時間読めるトークン（`yomi_prv_` で始まる） |
| 回答API | 公開済みの記事に基づいて、出典付きで訪問者の質問に答える API |
| 中継サーバー | 訪問者とCMSの間に立つ、サイトのサーバー。ブラウザから CMS は呼ばせません |
| 判定先行のストリーミング | 回答の本文より先に「答えられるか」を返し、検証してから本文を流す方式 |
| 質問ログ | 答えられなかった質問と、日ごとの件数の記録。既定では残しません |
| 埋め込み | 記事の内容の近さを計算するための数値の列。検索と関連記事に使います |
| チャンク | 埋め込みを作る単位に分けた、記事の断片 |
| 予算 | ワークスペースが使える LLM のトークン数の上限（訪問者向けの回答、編集者向けの支援、埋め込みの作成の3つ） |
| 天井 | サーバー管理者が決める、ワークスペースの予算の上限の上限 |
| 重い権限 | ロールの既定に加えて、個人に付与できる権限 |
| 再認証 | 重い操作の前の、もう一度の本人確認（画面では「本人の確認」） |
| 外部への送信の共通の仕組み | Webhook、LLM、OIDC、フックからの通信がすべて通る仕組み。内部向けの宛先には送りません |
| 内部宛先の例外 | 外部への送信で、例外として許す内部の宛先。ローカルの LLM や社内の IdP に使います |
| 監査ログ | 重い操作の記録。追記だけで、管理者でも編集や削除はできません |
