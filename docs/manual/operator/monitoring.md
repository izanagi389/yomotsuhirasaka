# 監視と監査ログ

## 見ておくもの

| 何を | どこで |
|---|---|
| サーバーが動いているか | `GET /healthz`（`ok` を返します） |
| サーバーのログ | 標準エラー出力（`docker compose logs yomi`）。パスワード、トークン、API キー、Cookie、記事の本文、質問文は出しません |
| ディスクの空き | メディアの保存先と PostgreSQL のボリューム |
| バックアップが成功しているか | [バックアップと復旧](backup.md) |
| 管理者への通知 | 「サーバーの管理」→「通知」と、下の書き出し |

## 管理者への通知

次のものは、監査ログに「知らせる」印が付いて、書き出し先と管理画面に出ます。

- ログインの失敗の急増、回数の制限への到達の急増
- 多要素認証のリセット、サーバー管理者の作成、緊急停止、監査ログの書き出し先の停止など

インスタンス単位のものは「サーバーの管理」→「通知」に直近7日の分が出ます。ワークスペースのものは、そのワークスペースの管理者の「やること」に出ます。「確認した」は自分の一覧から消すだけで、記録は監査ログに残ります。

急増の通知には、件数の多い IP アドレス、利用者の ID、メールアドレス（存在するアカウントのものだけ）が入ります。

急増のしきい値は `[alerts]` で決めます。

| 項目 | 既定 | 内容 |
|---|---|---|
| `login_failures` | 30 | ログインの失敗の件数 |
| `rate_limited` | 100 | 回数の制限への到達（429）の件数 |
| `window_seconds` | 300 | 数える期間 |
| `cooldown_seconds` | 1800 | 同じ種類を知らせる間隔 |

## 本人への通知

SMTP を設定すると、新しい端末や国からのログイン、パスワードや多要素認証の変更、API キーや個人トークンの発行を、本人にメールで知らせます。国の判定には [`geoip_database`](config.md#ログインの履歴login_history) が要ります。

## 監査ログ

重い操作（ログイン、権限の変更、キーの発行と失効、LLM の設定と予算の変更、質問ログの閲覧、デプロイ、訂正、抹消など）を記録します。

- 記事の本文や質問文は入りません。ID と操作の種類だけです。
- 追記だけです。管理者でも、管理画面や管理 API から編集や削除はできません。DB の権限でも守っています。
- インスタンスのログは「サーバーの管理」→「監査ログ」で、サーバー管理者だけが見られます。ワークスペースのログは、そのワークスペースの管理者が見られます。

保存期間は `[audit] retention_days` で決めます（既定は365日、30以上。インスタンスで1つ）。過ぎたものは自動で消えます。ただし、書き出し先に送り終えていないものは残します。

## 監査ログの書き出し

すべての記録を外に書き出せます。**管理者のアカウントが乗っ取られても消せない場所に残すため、書き出すことを勧めます。** 外に出したものは CMS の自動削除の対象外なので、保管は運用者の責任です。

```toml
[audit_export]
stdout = true                            # 標準出力に書く（サーバーのログは標準エラー出力なので混ざりません）
file = "/data/audit.jsonl"               # 追記するファイル

[[audit_export.webhooks]]
url = "https://logs.example.com/yomi"
secret_file = "/data/audit-webhook.secret"   # 署名の秘密のファイル
```

1行1件の JSON です。

```json
{"type":"audit","id":"…","at":"2026-11-08T12:00:00.000000Z","workspaceId":"…","actorUserId":"…","action":"entry.published","targetIds":["…"],"notify":false}
```

- 記録の順に最大100件ずつ、まとめて送ります。失敗したらやり直します。
- 7日間続けて送れないと「停止」し、再開するまで送りません。止まったことは、サーバーのログ（error）と管理者への通知に出ます。止まっている間に保存期間を過ぎて消えた記録は送れません。
- ワークスペースの書き出し先は、管理者が画面の「再開」で続きから送れます。
- 設定ファイルの書き出し先は、送り先を直してから、次のコマンドで続きから再開します。再起動は要りません。

  ```bash
  docker compose exec yomi yomi-server resume-audit-export --config /data/config.toml
  ```
- 設定ファイルから外した書き出し先は、次の起動で止まり、サーバー管理者に通知が出ます。止まった書き出し先には、保存期間を過ぎた記録の削除を待たせません。同じ書き出し先を設定に戻すと、次の起動で続きから送ります。
- サーバーを複数動かすときは、`[audit_export]` を同じにしてください。設定が違うサーバーが起動すると、ほかのサーバーが使っている書き出し先も止まります。
- Webhook の署名は [記事の Webhook と同じ書式](../developer/webhooks.md#監査ログの書き出し先) です。

ワークスペースの管理者も、自分のワークスペースの記録の書き出し先を「管理」→「監査ログ」で作れます。

## ログインの履歴

本人が「アカウント」→「セッションと履歴」で見られます。90日で自動で消えます（[`[login_history]`](config.md#ログインの履歴login_history)）。
