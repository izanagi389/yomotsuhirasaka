# テンプレートとCLI

CLI の入れ方は [最初のサイトを作るまでの流れ](getting-started.md#1-cli-とモジュールをソースからビルドする) にあります。

## コマンドの一覧

| コマンド | 内容 | トークン |
|---|---|---|
| `yomi deploy <フォルダ> --url <CMSのURL>` | テンプレートをデプロイする | デプロイの範囲 |
| `yomi schema build <フォルダ> [--out <ファイル>]` | マニフェストを書き出すだけ | 不要 |
| `yomi node scaffold <名前> --template <フォルダ> [--inline]` | カスタムノードの雛形を作る | 不要 |
| `yomi import <フォルダ> --url <CMSのURL> --workspace <ID> --redirects <出力>` | 既存のブログを取り込む | 読むと書くの範囲 |

トークンは環境変数 `YOMI_TOKEN` で渡します（引数に書くと、プロセスの一覧に出るためです）。トークンは管理画面の「アカウント」→「個人トークン」で発行します。

終了コード: 0 成功、1 デプロイしなかった・取り込まなかった、2 使い方の誤り、3 予期しないエラー。

## テンプレートの書き方

テンプレートは `templates/<テンプレート名>/template.json` に書きます。フォルダの名前がテンプレートの名前です。`$schema` に `cli/schema/template.schema.json` を指定すると、エディタで補完と検証が効きます。

```json
{
  "$schema": "../../cli/schema/template.schema.json",
  "locales": ["ja", "en"],
  "defaultLocale": "ja",
  "body": { "embedProviders": ["www.youtube.com"] },
  "contentTypes": [
    {
      "name": "post",
      "label": { "ja": "記事", "en": "Post" },
      "urlTemplate": "https://example.com/{locale}/blog/{slug}",
      "titleField": "title",
      "summaryField": "summary",
      "listLimit": 50,
      "review": { "intervalDays": 365 },
      "aiMarkdown": { "title": "title", "meta": ["summary"], "fields": ["body"], "relations": ["related"] },
      "fields": [
        { "name": "title", "label": { "ja": "タイトル", "en": "Title" }, "type": "text", "required": true, "searchable": true, "description": "記事のタイトル" },
        { "name": "slug", "type": "slug", "required": true },
        { "name": "summary", "type": "text" },
        { "name": "body", "type": "richtext", "required": true, "searchable": true },
        { "name": "related", "type": "reference", "referenceTo": "post", "multiple": true }
      ]
    }
  ]
}
```

### 全体

| 項目 | 内容 |
|---|---|
| `locales` | コンテンツのロケール |
| `defaultLocale` | 既定のロケール（`locales` のどれか） |
| `body.embedProviders` | 埋め込みを許す提供元のホスト名。https の URL だけを受け付けます |
| `body.customNodes` | カスタムノード（[関数](functions.md#カスタムノード)） |
| `contentTypes` | コンテンツタイプ |

本文の標準のノードとマークは書きません。CLI が、管理画面と同じ Tiptap の拡張機能から書き出します。

### コンテンツタイプ

| 項目 | 内容 |
|---|---|
| `name` | 英小文字で始まる英小文字、数字、`_`。DB と GraphQL の名前の元になります |
| `urlTemplate` | 公開 URL のテンプレート。使える差し込みは `{locale}` と `{slug}` |
| `urlFunction` | テンプレートで書けない URL を作る関数（あれば `urlTemplate` の代わりに使います） |
| `titleField` | 記事のタイトルのフィールド（text）。訂正フィードや一覧で記事の名前に使います。管理画面では本文の上に大きく出し、AI のタイトル案の当て先にもなります |
| `summaryField` | 記事の要約のフィールド（text。`titleField` とは別のもの）。AI の要約の案の当て先です。なければ要約の案は出ません |
| `hooks` | フック（[関数](functions.md)） |
| `review.intervalDays` | 確認期限の既定（1〜3650日）。なければ期限なし。記事ごとに変えられます |
| `aiMarkdown` | AI 向けの Markdown 版に載せるもの。挙げていないフィールドは載せません。なければ、このタイプの記事は AI 向けの素材になりません |
| `listLimit` | 一覧で1回に取得できる件数の上限 |
| `label` | 管理画面に出す名前。管理画面の言語ごとに `{ "ja": "記事", "en": "Post" }` と書きます（書けるのは `ja` と `en` だけ、50文字まで、1行）。管理画面の言語の名前がなければ `name` がそのまま出ます |
| `description` | 編集者向けの説明（管理画面に出ます） |
| `devNote` | 開発者向けのメモ。**どの API にも出ません** |

### フィールド

| 項目 | 内容 |
|---|---|
| `name` | 英小文字で始まる英小文字、数字、`_` |
| `type` | 下の「フィールドの型」 |
| `required` | 公開に必須か（スラッグは常に必須） |
| `referenceTo` | 参照先のコンテンツタイプ（参照のフィールドだけ） |
| `multiple` | 複数の値を持つか（参照と選択肢のフィールドだけ） |
| `integer`、`min`、`max` | 整数だけにするか、最小値と最大値（どちらもその値を含む）。数値のフィールドだけ |
| `options` | 選べる値（選択肢のフィールドだけ） |
| `fields`、`maxItems` | 中のフィールドと、件数の上限（グループのフィールドだけ） |
| `searchable` | 検索と質問応答の対象か。**既定は対象外**です。使えるのは `text` と `richtext` だけです（グループの中の `text` にも付けられます） |
| `label`、`description`、`devNote` | コンテンツタイプと同じ。`label` は入力欄の名前になります |

### フィールドの型

| 型 | 値 |
|---|---|
| `text` | 1行の文字列 |
| `slug` | URL に使う文字列（英小文字、数字、ハイフン） |
| `richtext` | 本文（Tiptap の JSON） |
| `reference` | 他の記事への参照 |
| `image` | 画像1枚（サムネイルなど） |
| `number` | 数値。`integer: true` なら整数（32ビット）、なければ小数。金額は整数で持ってください |
| `boolean` | 真偽値 |
| `date` | 日付（`YYYY-MM-DD`。時差を持ちません） |
| `datetime` | 日時（時差の付いた ISO 8601。例: `2026-11-25T10:00:00+09:00`）。UTC にそろえて保存し、秒まで持ちます。0 でない秒未満の端数は受け付けません |
| `select` | 選択肢。`options` の値から選びます。`multiple: true` なら複数を選べます |
| `group` | いくつかのフィールドのまとまりを、`maxItems` 件まで繰り返し持ちます（例: FAQ の「質問と答え」） |

ファイル（PDF などの添付）と、形を決めない JSON の型はありません。

値は保存のときにサーバーで確かめ、型に合わない値（選択肢にない値、範囲の外の数、実在しない日付など）は保存しません。必須かどうかは、公開のときに確かめます。

```json
{ "name": "rating", "type": "number", "integer": true, "min": 1, "max": 5 },
{ "name": "event_date", "type": "date" },
{ "name": "category", "type": "select", "options": [
  { "value": "news", "label": { "ja": "お知らせ", "en": "News" } },
  { "value": "howto", "label": { "ja": "使い方", "en": "How-to" } }
] },
{ "name": "topics", "type": "select", "multiple": true, "options": [{ "value": "rust" }, { "value": "nuxt" }] },
{ "name": "faq", "type": "group", "maxItems": 30, "fields": [
  { "name": "question", "type": "text", "required": true, "searchable": true },
  { "name": "answer", "type": "text", "required": true, "searchable": true }
] }
```

- **選択肢**: `value` は保存し配信 API で返す値で、フィールドの名前と同じ決まり（英小文字で始まる英小文字、数字、`_`、40文字まで）です。1つのフィールドに100個まで。`label` は管理画面にだけ出ます（書き方はフィールドの `label` と同じ。なければ `value` が出ます）。
- **グループ**: 中に置けるのは `text`、`number`、`boolean`、`date`、`datetime`、`select`、`image`、`reference` です。`slug`、`richtext`、グループの入れ子は置けません。中のフィールドは200個まで。`maxItems` の既定は20、最大は100です。`id` は各件の ID に使うので、中のフィールドの名前にできません。
- グループの各件には、サーバーが固定の ID（`i-` で始まる文字列）を付けます。並べ替えや書き直しでは変わりません。本文の見出しのアンカーと同じく、サイトでは各件の要素にこの ID を付けてください。質問応答の引用はこの ID を指します（`記事の URL#ID`）。消した件は削除されたセクション（`deletedAnchors`）に入ります。
- グループの中の `searchable` な `text` は検索と質問応答の対象になります。1件が1つのまとまりで、「名前: 値」の行をスキーマの順に並べたものです。
- `aiMarkdown.fields` にグループを挙げると、AI 向けの Markdown 版に、グループごとの節と、件ごとの小見出し（ID 付き。見出しの文は最初の `text` の値）が入ります。画像と参照は URL で載ります。

多言語は記事ごとです。ロケールごとに、すべてのフィールドを持つ独立した記事を作り、翻訳グループで結びます。参照フィールドは翻訳グループを指し、配信のときに同じロケールの公開中の記事に解決します（なければ返しません）。

## デプロイ

デプロイできるのは、多要素認証を設定したサーバー管理者だけです。**マニフェストに JS が入るので、デプロイの権限はサーバーの上でコードを動かす権限と同じです。** そのため、デプロイの範囲のトークンはほかの範囲と混ぜられず、有効期限は最長30日です。CI で使うときは、期限の前に発行し直してください。

```bash
YOMI_TOKEN=<デプロイの範囲の個人トークン> yomi deploy templates/blog --url https://yomi.example.com --dry-run
```

```bash
YOMI_TOKEN=<デプロイの範囲の個人トークン> yomi deploy templates/blog --url https://yomi.example.com
```

- CLI はまずサーバーで試行し（何も書き込みません）、マニフェストの問題、破壊的な変更、壊れる登録済みのクエリを表示します。判定はサーバーが行い、デプロイのときにもう一度検査します。
- `--dry-run` は試行だけで終わります。
- テンプレートを変えてデプロイすると、それを使う**すべてのワークスペース**に反映されます。ワークスペース固有の構造が要るなら、別のテンプレートを作ってください。
- サーバーが持つのは、テンプレートごとに最後にデプロイしたものだけです（版の番号はありません）。CLI には、最後にデプロイした日時が出ます（同梱のテンプレートは、管理画面の「サーバー」→「テンプレート」にも出ます）。同じ内容をもう一度デプロイしても変わらず、まだスキーマが入っていないワークスペースにだけ適用します。

### 破壊的な変更

フィールドの削除や型の変更は、`--allow-destructive` がなければ止まります。次の順に分けてください。

1. 新しいフィールドを追加してデプロイする。
2. データを移す。
3. 古いフィールドを削除してデプロイする。

型の変更には、`multiple` と `integer` と `referenceTo` の変更も含みます。

型を変えずに、受け付ける値を狭める変更も破壊的な変更です。最小値を上げる・最大値を下げる（新しく付けるのを含む）、選択肢を外す、グループの `maxItems` を減らす、グループの中のフィールドを外す・型を変える・必須にする・狭める、が当たります。選択肢を足す、範囲を広げるのは破壊的ではありません。

狭める変更は、`--allow-destructive` を付けても、新しい定義に合わない値を持つ記事（下書き、公開中の版、予約版のどれか）が1件でもあれば止まります（下の `value_violates`）。先に記事の値を直してください。グループの中の必須のフィールドは、公開中の版と予約版でだけ確かめます（下書きは書きかけでかまいません）。

グループの中で外したフィールドと型を変えたフィールドの値は、下書きから取り除きます。公開中の版と予約版には残りますが、配信では読みません。

### 登録済みのクエリを壊す変更

登録済みのクエリが1つでも壊れるなら、デプロイ全体を止めます（どのワークスペースにも適用しません）。CLI は壊れるクエリを表示し、終了コード 1 で終わります。

サイトのクエリを直して登録し直すか、使わないクエリを消してから、もう一度デプロイしてください。壊れるクエリがあっても適用するときは、`--allow-broken-queries` を付けます。そのときは、すべてのワークスペースに適用し、そのクエリは失敗するようになります。

同じテンプレートを使うすべてのワークスペースのクエリを確かめます。そのため、あるワークスペースの `register` のキーを持つ人が合わないクエリを登録すると、同じテンプレートを使うほかのワークスペースへのデプロイも止まります。1つのテンプレートを1つのワークスペースで使う運用なら影響はありません。複数のワークスペースで使うときは、`register` のキーを渡す相手に注意し、止まったときはクエリを確かめたうえで `--allow-broken-queries` で通してください。

長く使われていないクエリ（既定は90日）は検証しません。ビルドのたびの再登録も「使用」に数えます。

### 移行の失敗

そのテンプレートを使うすべてのワークスペースの移行を、まとめて1回で行います。1つでも失敗すれば、デプロイ全体を取りやめ、どのワークスペースもデプロイの前のままにします（`migration_failed`。失敗したワークスペースと理由のコードを表示します）。失敗は監査ログに残ります。原因を直してから、もう一度デプロイしてください。

移行の前に、新しいテンプレートに合わないデータがないかを確かめます。理由のコードは次のとおりです。

| コード | 意味 | 直し方 |
|---|---|---|
| `required_value_missing:<タイプ>.<フィールド>` | 必須にするフィールドが空の、公開中の記事がある | 記事に値を入れて公開し直す |
| `scheduled_value_missing:<タイプ>.<フィールド>` | 必須にするフィールドが空の予約版がある（予約版は予約したときの内容のまま公開されるため） | 予約を取り消すか、値を入れて予約し直す |
| `locale_in_use:<ロケール>` | 外すロケールの記事がある | その記事を削除する |
| `body_node_in_use:<名前>` | 外すノードやマークを、公開中の記事か下書きの本文で使っている | 本文から外す |
| `scheduled_body_node_in_use:<名前>` | 外すノードやマークを、予約版の本文で使っている | 予約を取り消すか、本文から外して予約し直す |
| `value_violates:<タイプ>.<フィールド>:<記事のID,…>` | 狭めた定義に合わない値を持つ記事がある（記事の ID は最大10件） | 記事の値を直す（予約版なら予約を取り消すか、直して予約し直す） |

## 既存のブログからの取り込み

Markdown のフォルダから記事を取り込みます。

```bash
YOMI_TOKEN=<読むと書くの範囲の個人トークン> yomi import ./content --url https://yomi.example.com --workspace <ワークスペースID> --config import.json --redirects redirects.json --static-dir ./public
```

- すべてのファイルを先に検査し、1つでも問題があれば何も取り込みません。
- 取り込んだ記事は公開されます。元の URL は、新しい URL との対応として URL の変更履歴に残ります。
- `redirects.json` には、Nuxt の `routeRules`（元の URL のパス → 新しい URL のパス、301）を書き出します。
- 代替テキストのない画像は「飾り」として取り込み、警告を出します。
- 画像はフォルダの中のファイルだけを読みます（`/` で始まるパスは `--static-dir` の中）。外部の URL の画像は取り込めません。
- 画像のフィールド（`image`）には、frontmatter に画像のパスを書きます（例: `thumbnail: ./images/a.jpg`）。代替テキストは `<フィールド名>Alt`（例: `thumbnailAlt`）に書きます。なければ「飾り」として取り込み、警告を出します。

設定ファイル（JSON、すべて省略可）:

| キー | 既定 | 内容 |
|---|---|---|
| `contentType` | コンテンツタイプが1つならそれ | 取り込み先のコンテンツタイプ |
| `originalUrlKey` | `url` | 元の URL を持つ frontmatter のキー（値は必須） |
| `localeKey` | `locale` | ロケールのキー（なければ既定のロケール） |
| `translationKey` | なし | 翻訳グループにまとめるキー |
| `translationOf` | なし | 元の記事のスラッグを指すキー |
| `bodyField` | 本文のフィールドが1つならそれ | 本文を入れるフィールド |
| `componentMap` | `{}` | 独自部品（`<Callout>`、`::callout`）→ 本文のノード。対応のない部品があれば止めます |
| `ignoreKeys` | `[]` | 取り込まない frontmatter のキー。フィールドにないキーは、ここに書かないと止めます |

**取り込む内容を確かめてください。** 元の URL がサイトと同じオリジンなら、そのページから記事への 301 ができます。CMS の外のページの URL を書くと、そのページが奪われます。取り込みは管理者と編集者だけが行えます。
