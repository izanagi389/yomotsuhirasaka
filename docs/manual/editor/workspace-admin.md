# ワークスペースの管理者の章

管理者は、多要素認証を設定しないと管理の操作ができません。重い操作の前には「本人の確認」が求められます。

## 所属者と招待

「管理」→「所属者」「招待」で扱います。

- **招待**: メールアドレスとロールを指定して「招待する」を押します。本人が承諾して初めて所属します。
  - サーバーに SMTP が設定されていないと、ワークスペースの管理者は招待できません。サーバー管理者に頼んでください。
- **ロールの変更と所属から外す**: すぐに効きます。その人の記事や版は残ります。ワークスペースには少なくとも1人の管理者が要ります。
- **重い権限**: ロールの既定に加えて個人に付与します（[一覧](../reference/roles-and-permissions.md#重い権限)）。付与と取り消しは監査ログに残ります。
- **パスワードや多要素認証のリセット**: 「パスワードのリセットを発行」「多要素認証のリセットを発行」で、本人向けのリンクを発行します。新しいパスワードを直接決める操作はありません。発行できるのは、**あなたが管理者であるワークスペースにしか所属していない人だけ**です。それ以外の人（ほかのワークスペースにも所属する人やサーバー管理者）には発行されず、本人に「リセットが求められたが発行されなかった」ことがメールで届きます。画面の表示は発行したときと同じなので、ほかのワークスペースへの所属は分かりません。必要ならサーバー管理者に頼んでください。次の場合も、サーバー管理者に頼みます。
  - サーバーにメールの送信（SMTP）が設定されていないとき。
  - シングルサインオンだけでログインする人のパスワードのリセット。まず IdP で回復してもらいます。

## 配信APIのキー

「管理」→「配信APIのキー」で発行します。**キーは発行のときに一度だけ表示されます。**

- 権限は「読む」「クエリの登録」「回答API」を必要な分だけ選びます。用途（ビルド用、サーバー用）は回数の制限の既定値を変えます。
- 「回答API」のキーは、呼ぶたびに LLM の料金がかかります。中継するサーバーにだけ置いてください。
- 漏れたかもしれないキーは、すぐに「失効させる」を押して、新しいキーに入れ替えてください。

## Webhook

「管理」→「Webhook」でサイトの受け口を登録します。署名の秘密は一度だけ表示されます。「テスト送信」と「送信の記録」で確かめられます。受ける側の作り方は [Webhookの受け方](../developer/webhooks.md) にあります。

## フックの秘密

「管理」→「フックの秘密」で、テンプレートのフックが外部の API を呼ぶときのキーなどを登録します。テンプレートの開発者に、どの名前で何を登録するかを聞いてください（[組み込みJS](../developer/functions.md)）。

1. 「名前」（英字で始まり、英数字と `_` だけ。例: `ANALYTICS_API_KEY`）と「値」を入れて「保存」を押します。同じ名前で保存すると、値を入れ替えます。
2. **値は暗号化して保存し、登録の後は表示しません。** 一覧には名前と更新の日時だけが出ます。

- 読めるのは、テンプレートで権限と名前を宣言した非同期のフックだけです。関数のソースにキーを書かせないでください。
- 「削除」を押すと確認が出ます。削除すると、その名前を読むフックは値を受け取れなくなります。
- 登録・削除は監査ログに残ります（値は残りません）。
- キーが漏れたかもしれないときは、外部のサービスの側でキーを作り直し、ここで値を入れ替えます。

## ワークスペースの設定

「管理」→「設定」にあります。

- **編集の引き継ぎ**: 誰が引き継げるかを選びます。
- **プレビュー**: 「プレビューを許すサイト」（`https://example.com` の形で最大10件）と「サイトのプレビュー用のパス」（公式の Nuxt モジュールの既定は `/_yomi/preview`）。
- **質問ログ**: 下の節を見てください。
- **関連記事の再計算**
- **危険な操作**: ワークスペースの削除（サーバー管理者だけ）。

### テンプレートの切り替え

「管理」→「テンプレート」で、ワークスペースのテンプレートを、デプロイ済みの別のテンプレートに切り替えます。この項目は、切り替えられる人にだけ出ます。行えるのは、サーバー管理者と、重い権限「テンプレートの切り替え」をサーバー管理者から付与された管理者だけです。

1. 「切り替え先のテンプレート」を選びます。今のコンテンツタイプとフィールドを、新しいテンプレートのどれに引き継ぐかの案が出ます（最初は名前と型が同じものを選んでいます）。この時点では何も変わりません。
2. 引き継ぎ先を直します。型の違うフィールドには引き継げません。「（引き継がない・消す）」を選んだものは消えます。新しいテンプレートにだけあるものは空で始まります。
3. 消えるデータがあると、その一覧が出ます。「消えるデータを書き出す（JSON）」で、消える値（下書きと過去の版）と、消えるコンテンツタイプの記事を書き出せます。本人の確認が求められます。
4. 「データが消えることを確認しました」を選び、「切り替える」を押して本人の確認をします。

- **過去の版も新しいテンプレートの形に置き換わります。** 引き継がないフィールドの値は過去の版からも消え、元に戻せません。版の番号・日時・訂正の記録は残ります。
- 引き継がないコンテンツタイプの記事は削除されます。
- 切り替えは監査ログに残り、管理者に通知されます。
- 登録済みのクエリが動かなくなるときは、その一覧が出ます。サイトのクエリを直してから切り替えるか、確認して切り替えます。
- 切り替えの後、公開中の記事の変換結果・検索用データ・公開URLを作り直します。URL が変わった記事には、変更の履歴とリダイレクトが残ります。

「管理」→「訂正の定型文」で、訂正の説明の定型文と、説明がないときの文をロケールごとに決めます。

## 予算

「予算」で、3つの予算の使用量と上限を見て、変えられます（権限「LLMの接続設定と予算」）。

| 予算 | 尽きたとき |
|---|---|
| 埋め込みの作成の予算 | 作成を止め、それまでの埋め込みで動き続けます。訪問者の検索語と質問文の分は、同じ上限で別に数えます。尽きるとキーワード検索だけで動きます |
| 訪問者向けの回答の予算 | 回答 API が予算切れのエラーを返します |
| 編集者向けの支援の予算 | AI 支援だけが止まります。公開は妨げません |

- トークン数で数えます。月と日は UTC の暦で区切ります。
- 上限はサーバー管理者が決めた「天井」の範囲で決められます。天井が 0 なら LLM を呼びません。上げるにはサーバー管理者に頼んでください。
- 尽きたら「やること」に出ます。上限を上げるか、次の期間になると再開します。

## チャットボット

「チャットボット」で、回答の語り口と答えられないときの文を決めます（権限「LLMの接続設定と予算」）。**引用の検証は、どの設定でも必ず行います。**

- **答えない質問**: 拒否する語を決めると、その語を含む質問には答えません。質問文は LLM にも埋め込みにも送らず、質問ログにも残しません。クレジットカード番号やマイナンバーらしい並びを断るスイッチもあります。
- **回答を試す**: テスト用の質問で、検索された断片と点数、AI の判定、回答を確かめられます。訪問者向けの回答の予算を使います。回答キャッシュは使わず、質問ログにも残りません。
- **自由記述のシステムプロンプト**: 語り口の指示としてだけ使われます。指示によっては回答の正確さが下がることがあります。

### 訪問者の質問の扱い

**訪問者の質問文は、外部の LLM の提供会社に送られます。** メールアドレス、電話番号、IP アドレスなどの決まった形は伏せますが、**氏名や住所のような自由な書き方は伏せられません。** 機密性の高いサイトでは、ローカルの LLM をサーバー管理者に相談してください。

## 質問ログ

既定では残しません。「管理」→「設定」の「質問ログを残す」で有効にします。

- **サイトのプライバシーポリシーへの記載が必要です。**
- 残すのは、答えられなかった質問（決まった形を伏せたもの）です。答えた質問は日ごとの件数だけです。保存期間を過ぎたものは消えます。
- 見るには「質問ログの閲覧」の権限が要ります。**管理者にも既定では付きません。** 閲覧は監査ログに残ります。
- 「質問ログ」の「書くべき記事の候補」から「構成案を作る（AI）」を押すと、記事の構成案を作れます（AI 支援が有効なとき）。
- 無効に戻すと、残っている質問文はすぐに削除され、元に戻せません。

## 編集者向けのAI支援

「チャットボット」の画面の「AI支援を使う」で有効にします（権限「LLMの接続設定と予算」）。**公開前の下書きが外部の LLM の提供会社に送られます。** 機密性の高いサイトでは、ローカルの LLM を勧めます。

## LLMの接続設定の上書き

サーバー管理者が許したときだけ、「予算」の画面の「LLMの接続設定（このワークスペース）」で、許可された接続先と自分の API キーを選べます。保存したキーは表示されません。埋め込みのモデルを変えると全記事の埋め込みを作り直すので、見積もりを見てから開始してください。

## 監査ログ

「管理」→「監査ログ」で、このワークスペースの重い操作を見られます。記録は操作の種類、操作した人、対象、時刻だけで、内容は含みません。管理者でも編集や削除はできません。サーバー管理者がこのワークスペースを操作した記録も、ここに出ます。

「書き出し先（Webhook）」を追加すると、1行1件の JSON で外に送れます。

## もし怪しいと思ったら

- キーが漏れたかもしれない: 「配信APIのキー」で失効させて入れ替えます。
- アカウントが乗っ取られたかもしれない: その人の所属を外し、サーバー管理者に連絡します。
- サーバー全体の問題かもしれない: サーバー管理者に連絡します（[事故対応](../operator/incident.md)）。
