# 持ち主のブログでの確認（v1.0 の候補の版）

`docs/decisions/14-release.md` の「持ち主のブログでの確認」の手順です。公式の Docker Compose で動かすブログを `v1.0.0-rc.N` に上げて、手順書のとおりに導入・更新・バックアップ・復旧ができるかを確かめます。

- 実行するのは持ち主です。各項目の **結果** の欄に、出力や気づいたことを貼ってください。判断は Claude が行います。
- コマンドは `docs/manual/operator/` のものをそのまま使います。手順書と違うことをしたら、その内容も書いてください（手順書の誤りを見つけるのが目的の1つです）。
- 出力に秘密の値（パスワード、キー、トークン、TOTP の秘密）が出たら、貼る前に伏せてください。

## 1. 導入（新しく入れる場合）

`docs/manual/operator/install.md` のとおりに進めます。すでに動いているなら 2 へ。

| # | 確かめること | 結果 |
|---|---|---|
| 1-1 | `./init.sh` が通り、`data/` ができた。`config.toml` の `public_url` が https | |
| 1-2 | `docker compose up -d --wait` で、`db` と `yomi` が healthy になる | |
| 1-3 | `yomi-server create-server-admin` でサーバー管理者を作り、管理画面にログインし、多要素認証を設定できた | |
| 1-4 | DB のポートがホストの外から届かない（別のマシンから `5432` に接続できない） | |
| 1-5 | ワークスペースを作り、テンプレートを `yomi deploy` でデプロイできた | |
| 1-6 | 今の記事を `yomi import` で取り込めた（件数、旧 URL の変更履歴、リダイレクトの一覧） | |
| 1-7 | サイト（Nuxt モジュール）から記事、検索、訂正の一覧が見える。旧 URL が 301 で新しい URL に転送される | |
| 1-8 | サイト自身の固定のページ（`/about` など）が、旧 URL の転送で奪われていない | |
| 1-9 | SMTP の通知（新しい端末からのログイン）が届く | |

## 3. 復旧の練習

本番のブログを止めずに試すなら、別のマシン（または同じマシンの別のディレクトリと別のポート）に復旧します。`docs/manual/operator/backup.md` の「復旧する」のとおりに進めます。

| # | 確かめること | 結果 |
|---|---|---|
| 3-1 | `./init.sh` を実行せずに、ファイルを戻せた | |
| 3-2 | DB を戻したときのエラーが `role "postgres" already exists` の1つだけ | |
| 3-3 | `healthz` が `ok` を返す | |
| 3-4 | 管理画面にログインでき、多要素認証のコードが通る（鍵が合っている） | |
| 3-5 | 記事、画像、検索、ワークスペースの設定が戻っている。「移行待ち」がない | |
| 3-6 | バックアップの後に発行したキーが使えない（手順書のとおり） | |
